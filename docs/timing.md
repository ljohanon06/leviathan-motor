# Timing
## External Components
### Magnetic Encoder
The magnetic encoder is a MT6701. It has a minimum clock period of 64ns, the PLL generates a clock frequency of 15.43 MHz, or a clock period of 64.8ns. 24 bits are transmitted: 14 data bits, 4 status bits, and a 6 bit CRC checksum ($x^6+x+1$). An additional six clock cycles are used for CRC checking and chganging the CSN bit. These 30 clock cyles take 1944ns. SSI is used to communicate with the magnetic encoder.

The magnetic encoder will read if **enable** is high, it doesn't work on positive edge. The output **angle_out** is registered over if the crc matches and **done** sends a positive edge.

### ADC
The analog to digital converter is a MCP33151D. It is a 500 ksps ADC with 14 bits of resolution, max 100 MHz clock. A 101 MHz clock is generated from the PLL is used to talk to it. Two of them are used to measure the current on lines A and B. There is two phases to the ADC calculation: a capacitor charge phase which takes 600ns, and a data conversion phase which takes 1400ns. The capacitor charge phase is where the internal capacitor for the SAR ADC charges to the input voltage level. The data conversion phase is where the ADC takes the capacitor voltage and digitizes it. The capacitor must charge when the low side MOSFET is on. There is 141 data conversion clock cyles, 14 data clock out cycles, and 5 forced off cycles afterward, total 160 clock cycles.

The ADC starts if **start** is high, it waits the 1400ns for the data conversion phase. The data is shifted into **adc**, and **done** gets a positive edge when the device is done.

### Gate Driver
The gate driver used is a DRV8300D. It takes 6 pwm signals: high and low for inputs A, B, C. The max pwm frequency is 200kHz or 5000ns. The gate driver either requires, or manually enforces, a 200ns deadtime between the high and low edges. The algorithm first takes the signed normalized voltage for the line, biases it up to be positive, and scales it to be 10 bits. This provides 1024 different PWM lengths. 4600ns/1024 = 4.49ns or 222.6 MHz clock, the PLL provides 222.2. 

The output of the algorithm, done in voltage_normalizer.sv, returns the cycle count for which pwm is high. Cycle count low is equal to 1023-high. The voltage_normalizer algorithm also guarentees that the ADC will get at least 400ns to charge, not the full 600ns required. single_pwm.sv handles the actual pwm signal generation from these values, and triple_pwm handles the clock cycle count, and also tells the ADCs when to take measurements through a posedge signal. 

## Multicycle Modules
### CRC
The CRC (Cyclic Redundancy Checksum) is used to ensure no bits flipped during transmission. It is used by two different modules, the magnetic encoder which sends a 6-bit checksum over with its data transmission, and the monitor module for the FT232H. The magnetic encoder is only working at 15MHz, but it is next to the magnetic fields of the motor which could flip some bits. 

Due to the long combinational logic paths in the CRC module, any modules using the CRC must give it an additional clock cycle or multiple at higher clock speeds. This must also be set in the SDC file as a multicycle path.

### Forward and Inverse Transforms
The forward and inverse transforms are what convert the line currents to the normalized current, and the normalized voltage back to the phase voltages. These wrap the normal and inverse, clarke and park transforms which do the individual vector transforms. Each of these modules take 2 clock cycles, so in total the forward and inverse transforms take four clock cycles each.

### Cordic Algorithm
The cordic algorithm is a way to convert an angle to a cosine and sine values for that angle. It iteratively takes the cosine and sine value and moves them towards the true value. Each clock cycle adds roughly a bit of precision. Since we have 12 usable bits from the magnetic encoder, we do 12 clock cycles for the magnetic encoder. This is done with the cordic_full module and it requires those 12 clock cycles to function properly. A signal **done** is set when the output is ready.

## Timing Considerations
### ADC Offsets
Since the end goal of this project is run three motors, and since the FPGA we're working with has limited pins, we want the ADCs to share the clock and data pins. Since the ADC needs 1400ns to convert the data and another 150ns to clock the data out, this gives us around 350ns of slack for the three sets of ADCs. Because of this, the overall timing system has to coordinate the three ADCs to be offset by thirds. If this is feasible with the variable measurement times on the low side MOSFET is not known yet. 

### Clock Domains
There are four clock domains in the project. The first is the 60 MHz clock for the FT232H data transmission. It is generated by it and is fully handled by the ft232h_cdc.sv module. The next three are the clocks generated by the PLL: 15.43 MHz, 101.01 MHz, and 222.2 MHz. The 15.43 MHz clock is only for the magnetic encoder. The 101.01 MHz runs the main logic: the vector transforms, cordic, PI controllers, and the data transmission. The 222.2 MHz handles the PWM and only the PWM. Since the clock period is so short, there is no long logic chains that can be made for it.

### Data Path
For each motor, there is 5000ns to work with. There is also two main data transmission paths coming from either the ADC or the Magnetic Encoder. Any clock cycles mentioned here are 101.01 MHz clock cycles.

For the ADC measurement, this happens 600ns after the 200ns deadtime, so 800ns. The measurement signals generated from the PWM side for the ADCs take 2 clock cycles to switch clock domains, then the ADCs are ready 155 clock cycles later. This takes 4 clock cycles to get through the forward transform, some amount of time to pass through the PI controller, and 4 clock cycles to pass back through the inverse transform. Overall 165 clock cycles plus PI time plus 800ns for ADC. PI time is assumed at 50 clock cycles for now.

For the magnetic encoder measurement, it can be done at any time and takes 1944ns and another 2 clock cycles to switch clock domains. Then it needs 12 clock cycles for the cordic algorithm before being fed into the transform functions. This takes 2082ns in total. The ADC path needs the cordic values for the forward transform at 2354ns. After this, it takes 8 plus the assumed 50 clock cycles or 574ns. 

Overall, it takes around 3000ns for the full calculations to be made, more than enough for the 5000ns for a 200 kHz PWM.
